### Leading play: Challenge 4 CoGNETs auctions — breakdown for my use (track PDF in hand; [GUESS] only where noted). Hyperion breakdown retained below as the alternative.

- **Specific user persona:** a platform/DevOps engineer onboarding to HYPER-AI who lives in the IDE and prefers asking over clicking — e.g. "Marta, MSc student at UPV, first week on a HYPER-AI edge deployment, needs to scaffold, run and understand a sample without reading all docs."
- **What it does:** Hyperion, an agentic microservice in Python + Docker: (a) answers questions about HYPER-AI via RAG over project docs; (b) drives the IDE frontend on the user's behalf — create/edit/delete files, run actions; (c) streams progress over Server-Sent Events with session memory across turns; (d) every file mutation passes a deterministic workspace truth engine and pauses on destructive ops for Approve/Reject.
- **Why AI / why now:** IDE state + docs are too large to click through; only an LLM agent with retrieval + tool use can turn "set up the sample and explain why it failed" into one sentence. The event hands us the IDE + boilerplate precisely so the agent layer is the differentiator.
- **Business value:** named user (edge/IoT platform teams onboarding to HYPER-AI/aeriOS); revenue model [GUESS]: B2B per-seat IDE plugin + support; TAM anchor [unconfirmed — pin during PGM]: European edge-tooling / internal-developer-platform spend. Evidence via DECKGEN business-value slot with a named-user quote mined by PGM.
- **Demo story (60–90 s):** judge speaks/types "clone the sample, add a sensor node, explain the error" → agent streams SSE steps, file tree + 3D workspace graph update live, truth engine flashes 1 deliberate error → repair, human approves a delete, judge uploads their own repo file as real input (depth §1.1). Fallback ladder: recorded DEMODRIVE capture + mock-envelope replay if Wi-Fi dies.
- **Judging-axis strategy (how each axis gets evidenced):** Working-solution axis → live run + `run-trace.json` counts (model roles ≥3, verify→repair to 0 errors, checkpoint resolved) via DECKGEN/SUBMIT; Presentation → SCRIPT mm:ss blueprint opening on moving 3D + activity feed; Business value → FAQDEF Q&A with named-user + revenue-model rows; Originality → beyond-sample coverage line (TECH-LEVERAGE §3) + crowding memo showing we avoided the 5–10 crowded takes below.
- **Depth bar (per templates/product-depth.spec.md):** real input (judge's own file/repo + bundled sample, licensed + labelled); stateful domain (workspace file-graph store: id-addressable nodes, revision + undo; UI buttons and agent tools call the same store actions); ≥15 typed actions (Read/Create-Change/Verify/Navigate/Collaborate); multi-round call graph (perceive→plan→act→verify→repair→explain, expected total stated in plan, e.g. 1 perceive + 1 plan + 12 act + 2 verify + 2 repair + 1 explain = 19); deterministic truth engine (`check(workspace) → Issue[]` with severity/entityIds/message+units/fix-action; seed scenario regression = 0 issues; demo shows 1 deliberate error found + repaired); human authorship (direct file edits + Approve/Reject bar on destructive ops, rejection returns actionable sentence); visible execution (activity feed AGENT/YOU/SYSTEM + changed-element animation + manual runner over action schemas).
- **Signature 3D (per templates/3d-experience.spec.md) [GUESS]:** Subject: workspace dependency graph as a live 3D constellation (files = nodes, imports/calls = edges, error nodes pulse). Why 3D: "the workspace is a graph with depth and clusters." Live binding: agent `create/edit/delete` + human edits add/move/highlight nodes; `get_issues` paints error halos; `focus_entity` flies camera. Stack: three.js WebGLRenderer + @react-three/fiber/drei (OrbitControls, Text) + postprocessing (SSAO/Bloom) — default approved stack. Shots: `overview`, `focus:<file>`, `error-pulse`. Hero frame: "lit graph of the judge's own files with one red error node mid-repair."
